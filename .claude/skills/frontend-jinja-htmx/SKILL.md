# Фронтенд server-tracker: Jinja + HTMX

Проект — **server-rendered**: HTML собирает Jinja на бэкенде, браузер
получает готовую страницу. Никакого React/Vue/SPA, никакого сборщика,
никакого npm. Это осознанное решение (AGENTS.md → «Стек»): проект
должен оставаться читаемым человеком без опыта в вебе.

HTMX — точечный инструмент для подгрузки HTML-фрагмента без
перезагрузки страницы, а не архитектура приложения. Сейчас он
используется ровно в одном месте — поиск на дашборде
(`dashboard.html` → `/search` → `search_results.html`). Не расширять
его применение без явной необходимости: обычная форма с redirect
проще и надёжнее.

Alpine.js упомянут в AGENTS.md как часть стека, но **фактически нигде
не подключён**. Не считать его доступным и не подключать без
обсуждения с пользователем.

## Язык интерфейса

- Весь текст, который видит пользователь, — **на русском**. Имена
  переменных, комментарии в шаблонах (`{# ... #}`), CSS-классы — на
  английском.
- Backend-коды (`status`, `event_type`, роли, `image_slot`) выводить
  **только** через фильтр `label`:
  `{{ item.status | label('platform_status') }}`. Никогда не писать
  русскую подпись кода прямо в шаблоне — новое значение регистрируется
  в `app/i18n.py` (см. скилл `add-catalog-value`).
- Даты — только через `msk_date` / `msk_datetime`
  (`{{ c.installed_at | msk_date }}`). Не выводить сырой `datetime` и
  не форматировать дату в роутере — фильтры уже учитывают московское
  время и `None` (отдают «—»).

## Экранирование: главное правило

**Никогда не подставлять значение из БД внутрь JavaScript.** Это
единственная реальная XSS-дыра, которую здесь легко открыть, и в
проекте она уже есть — не копировать этот паттерн:

```jinja
{# ПЛОХО — значение из БД попадает в JS-строку #}
<form onsubmit="return confirm('Удалить файл «{{ f.original_filename }}»?')">
```

Автоэкранирование Jinja защищает **HTML**-контекст, но не JS-строку:
апостроф превращается в `&#39;`, браузер декодирует его обратно ещё до
того, как JS-движок разберёт код, и кавычка выходит из строки. Имя
файла или asset tag вида `a');alert(1)//` выполнит произвольный
скрипт в браузере того, кто откроет страницу (включая администратора).

Правильно — текст подтверждения без подстановки, либо значение через
`data-`-атрибут (там HTML-экранирование работает):

```jinja
<form onsubmit="return confirm('Удалить файл?')">
```

В обычном HTML-контексте (`<td>{{ x }}</td>`, `value="{{ x }}"`)
экранирование работает автоматически — там подставлять можно.
`| safe` в этом проекте не используется нигде; если рука тянется его
поставить — почти наверняка это ошибка.

## Структура страницы

1. `{% extends "base.html" %}` + `{% block content %}`. Заголовок
   вкладки — `{% block title %}`, если страница про конкретный объект.
2. Роутер должен импортировать `templates` из `app.templating` — там
   зарегистрированы фильтры `label` / `msk_date` / `msk_datetime`.
   Локальный `Jinja2Templates(...)` в роутере эти фильтры не увидит и
   страница упадёт.
3. Первой строкой контента — «хлебные крошки» вверх по иерархии
   (платформа / исполнение), последней — ссылка «← назад к родителю».
   Так сделано во всех страницах изделия и исполнения.
4. Пустое состояние — через `{% for %} ... {% else %} ... {% endfor %}`,
   отдельный `{% if not items %}` не нужен.
5. Таблицы с длинным содержимым — `<colgroup>` с процентными ширинами
   + класс `nowrap` на колонках дат и кнопок (иначе таблица расползается,
   это уже чинили).

## Ошибки и формы

- Формы — обычные `<form method="post" action="...">`. Успех — роутер
  отвечает redirect 303, браузер уходит на GET (F5 не повторяет
  мутацию).
- Ошибка — роутер рендерит **тот же самый шаблон** с переменной `error`
  и статусом 4xx. Значит в каждом шаблоне, куда роутер может вернуть
  ошибку, обязана быть строка вывода:
  `{% if error %}<p class="error">{{ error }}</p>{% endif %}`.
  Забыть её — значит показать пользователю страницу, где ничего не
  произошло и не объяснено.
- Текст ошибки приходит из роутера уже на русском — в шаблоне его не
  переводить и не дополнять.

## HTMX — что нужно помнить

- **htmx по умолчанию не вставляет ответ с кодом 4xx.** Он считает
  такой ответ ошибкой и оставляет страницу нетронутой. Это прямо
  конфликтует с принятым здесь способом сообщать об ошибке
  («шаблон + `status_code=409`»): если сделать форму htmx-овой, текст
  ошибки молча не отрисуется.
  Поэтому: htmx-эндпоинт либо всегда отвечает 200 (текст ошибки внутри
  фрагмента), либо на странице вешается обработчик `htmx:beforeSwap`
  с `evt.detail.shouldSwap = true`. Первое проще.
- Фрагмент для htmx — отдельный шаблон **без** `{% extends %}`
  (образец — `search_results.html`), иначе в `<div>` приедет целая
  страница вместе с шапкой.
- Роутер такого фрагмента возвращает `TemplateResponse`, не JSON —
  htmx вставляет ответ как HTML. (Раньше `/search` отдавал JSON, и
  поиск просто не отрисовывался.)
- Фрагмент отдаёт данные так же, как обычная страница: `label`, роли,
  экранирование — всё то же самое, это не «внутренний API».

## Роли в шаблоне

- Коммерческие данные (`item.customer` и любые заметки о заказчике) —
  строго под `{% if user.role != 'viewer' %}`. Пока UI полностью
  server-rendered, это и есть точка фильтрации (AGENTS.md → «Роли и
  доступ»).
- Кнопки/формы действий — под `{% if user.role in ('admin', 'engineer') %}`
  (удаление платформ/исполнений/файлов — `{% if user.role == 'admin' %}`).
- Это **только про внешний вид**. Скрытая кнопка не защищает эндпоинт:
  право обязано проверяться в роутере через `require_role(...)`. Скрыли
  в шаблоне — проверьте, что и роутер закрыт.

## Стили

- Один файл — `app/static/css/style.css`. Отдельных CSS на страницу нет
  и заводить не нужно.
- Цвета — только через переменные из `:root`; тёмная тема задана блоком
  `@media (prefers-color-scheme: dark)`. Новый цвет — это **две**
  правки: светлая переменная и тёмная. Хардкод hex в шаблоне
  (`style="color:red"`, такое место в проекте есть) — не копировать,
  использовать класс.
- Не подключать внешние CSS/JS с CDN. Проект должен подниматься одним
  `docker compose up` в сети без интернета (AGENTS.md → «Конвенции
  кода»); всё, что нужно браузеру, лежит в `app/static/`.
  Известное нарушение: `base.html` тянет htmx с `cdnjs.cloudflare.com`
  — при правке `base.html` заодно перенести файл в `app/static/js/`.
- Страница должна оставаться рабочей без JavaScript, где это дёшево
  (образец — `<noscript>`-кнопка у фильтра на дашборде).

## Чеклист перед завершением

1. Весь новый видимый текст — на русском, коды — через `label`, даты —
   через `msk_*`.
2. Ни одного значения из БД внутри `onsubmit`/`onclick`/`<script>`.
3. Есть вывод `{% if error %}`, если роутер может вернуть ошибку в этот
   шаблон.
4. Проверены обе роли: что видит `viewer`, что видит `engineer`.
5. Проверена тёмная тема, если добавлялись цвета.
6. Страница открыта в браузере (скилл `run`) — вёрстка не разъехалась.
